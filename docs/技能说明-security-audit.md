## 一句话介绍

**security-audit 就是给代码请的一位"保安队长"**:定期把整个项目巡视一遍,看看有没有"门窗没锁好"的地方——密码有没有乱放、代码有没有能被坏人钻空子的写法。

## 怎么用它

直接对我说以下任意一句话即可:

- "**安全检查**"
- "**安全审计**"
- "**查漏洞**"
- "**/security-audit**"

想只查某个文件?比如"**检查一下 db.js 的安全**",也行。

## 它会检查哪四件事

### ① 密码、密钥有没有"乱放"

**在找什么**:代码里有没有把真实的密码、钥匙、通行证**直接写在纸上**。

**为什么危险**:代码是要上传到 GitHub 的,相当于把自己家钥匙的照片贴在小区公告栏上,全世界都能看到。

**顺便还会查一个"隐藏角落"**:Git 的历史存档。哪怕你后来把密码从代码里删掉了,**历史存档里仍然留着旧版本**——就像撕掉日记的一页,但复印机早就复印过了。这种情况它也会告诉你。

### ② 注入漏洞(重点)

**什么是"注入"?打个比方**:你去餐厅点菜,正常是你报菜名"宫保鸡丁",厨师照做。但如果厨师太实在,你说"宫保鸡丁,**顺便把收银台的钱也给我**",他真照做了——这就是注入攻击:**把"命令"伪装成"普通内容"混进去,让电脑照做**。

**它会查**:
- **SQL 注入**:搜索框里输的关键词,是被当作"纯文字"去查,还是被当作"命令"执行?如果代码是"把关键词直接拼进查询语句",坏人就能在搜索框里搞破坏。
- **命令注入**:代码里有没有"执行系统命令"的地方掺了用户输入。
- **界面注入**:用户填的内容(比如备注)被直接当成网页代码显示,可能弹出假窗口骗人。
- **路径注入**:用用户输入拼文件路径,坏人可能借机读到别的文件。

### ③ 配置文件里的明文敏感信息

**在找什么**:那些"设置文件"里有没有写着不该写的秘密,包括:
- 下载源、权限设置文件里有没有明文密码、令牌、带账号密码的网址
- **特别重要的一项**:检查"忽略清单"(.gitignore)有没有把**账单数据文件(\*.db)、安装包、密钥文件**排除掉——这是防止你的记账数据被误传到 GitHub 的最后一道闸门

### ④ 其他安全隐患

- **软件的安全开关**:比如"网页界面能不能直接碰电脑文件"的几个开关,有没有设错(设错 = 大门敞开)
- **联网代码**:你的软件原则上是**完全离线**的,如果发现任何"往外发数据"的代码,它会立刻按最高警报上报
- **安全守则**:网页有没有配置"只允许加载本机内容"的守则
- **日志泄露**:有没有把用户数据打印到调试信息里
- **第三方材料的已知漏洞**:会**先问你同不同意**,同意后才联网检查

## 检查完的报告长什么样

报告分四档,按"危险程度"排序,全部大白话:

| 档位 | 含义 |
|---|---|
| 🔴 高危 | 必须修,坏人真能利用 |
| 🟡 中危 | 建议修,属于"门没插销"级别 |
| 🟢 低危/提示 | 可以不改,说明原因 |
| ✅ 做得好 | 已经到位的防护也列出来,让你心里有数 |

每条问题都会写:**在哪个文件、第几行、什么问题、坏人大体能利用它干什么**。

## 它的"三大纪律"

1. **只检查、不动手**:检查阶段绝对不碰你的代码,先给你看报告
2. **修不修你说了算**:报告最后会问你"要不要修",你点头才动手,修完还会验证软件能正常打开
3. **不擅自联网**:涉及要联网的检查(如查第三方材料漏洞),先问你同意

## 什么时候该用它

- 每次做完一批新功能,**准备上传 GitHub 之前**,顺手查一遍(推荐,几秒钟的事)
- 想往软件里加"联网"功能之前,先查一遍
- 单纯想安心的时候

## 和另外两个技能的分工

| 技能 | 管什么 | 好比 |
|---|---|---|
| git_save | 存档 + 上传 GitHub | 快递员 |
| comments-check | 注释够不够、准不准、小白能否看懂 | 语文老师 |
| **security-audit** | 有没有安全漏洞 | **保安队长** |

## 说句实在话(它的能力边界)

它是一位"按清单仔细巡视的保安",能查出**常见、已知**类型的隐患,比如密码乱放、搜索框拼接 SQL 这些经典问题。

但它**不是保险箱**,做不到 100% 保证"绝对没有漏洞"——世界上没有任何工具能做到(专业安全公司也要靠多轮人工排查)。它的价值在于:**把最常见、最容易犯的错误挡在门外**,让你上传代码时心里踏实。
